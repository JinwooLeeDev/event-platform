Busan Play 2-B 행사 콘텐츠 AI 다국어 연동 결과

주요 파일
- event/events/Event.java: EntityListeners 연결 1줄. DB 필드/스키마 변경 없음.
- event/events/EventService.java: 기존 생성자 유지, 상세/공개 목록 DTO 조합 후 번역 overlay.
- event/translation/EventTranslationLifecycle.java: 모든 JPA 저장/수정 경로의 PUBLISHED 행사 감지.
- EventTranslationRequested.java / EventTranslationAfterCommit.java: 원문 없는 식별자 알림과
  AFTER_COMMIT 요청 등록. 예외는 여기서 차단하며 공개/보증금 커밋을 훼손하지 않는다.
- EventTranslationPresentation.java: 선택 Locale에 따라 상세/목록 콘텐츠만 선택.
- EventTranslationService.java / TranslationStore.java: 일괄 완료 캐시 조회 추가.
- 테스트: EventTranslationPresentationTest.java / EventTranslationIntegrationTest.java.

공개·수정 시 연결
실제 공개 전환은 DepositService.payDeposit의 모든 회차 보증금 납부 완료 시점이다.
해당 업무 코드는 수정하지 않고 Event의 PostPersist/PostUpdate 알림으로 포착했다.
PENDING_REVIEW/PAID_READY/보완 상태는 번역 작업을 만들지 않는다.
PUBLISHED의 변경 후 커밋이 끝나면 기존 requestTranslation(eventId,"en")을 호출한다.
같은 원본 hash는 기존 캐시/작업 유일성에 따라 재번역하지 않는다.
title/summary/description 변경은 새 hash 작업을 생성한다. ja/zh-CN의 이전 hash 캐시는 사용하지 않는다.
이전 캐시를 강제로 지우거나 API/예산/재시도 정책을 변경하지 않았다.
기존 EventService의 PUBLISHED 직접 수정 금지 정책은 유지했다.
허용된 JPA 변경은 감지되지만 직접 SQL/bulk update는 entity lifecycle 대상이 아니다.

조회 표시
- ko: 조회/요청 없이 기존 원문.
- en: 공개/수정 시 등록된 완료 캐시만 사용. 조회 자체에서 새로운 영어 작업을 만들지 않음.
- ja/zh-CN: 완료 캐시가 없으면 커밋 후 기존 서비스로 등록하고 첫 응답은 원문 유지.
- 완료·동일 hash만 title/summary/description에 적용. 목록에는 기존 DTO가 가진 title/summary만 적용.
- PENDING/PROCESSING/FAILED/STALE/NOT_FOUND는 원문 그대로 표시.
- 목록/검색/메인은 동일 EventService.findAllPage 경로를 사용한다. 캐시는 페이지 단위 IN SELECT 1회.
  누락 항목의 작업 등록 시 기존 2-A의 개별 잠금·캐시 재확인은 동시성 보호를 위해 유지한다.
- 상세는 EventService.findById에서 같은 presentation을 적용한다.
- Controller/DTO 정의/Mustache/URL/검색/페이징/정렬/HTML escape는 변경하지 않았다.
  주소/장소/시간/상태/금액/인원은 원본을 유지한다. 관리/기업 수정 폼에도 원본을 유지한다.
- 부가 캐시 조회는 독립 트랜잭션이다. PostgreSQL SQL 오류가 기존 행사 조회 트랜잭션을
  중단시키지 않도록 분리하고, presentation에서 원문 fallback으로 처리한다.

최소 검증 결과
- 핵심 테스트 14개 통과: 커밋 전/롤백 시 미등록, 공개 후 등록, 같은 hash 재사용,
  원문 변경 후 stale/재등록, ja/zh-CN 최초 원문과 다음 캐시 표시, 상세·목록 DTO,
  원본/주소 보존, 캐시 hit API 비호출, 등록 오류/조회 오류 격리 포함.
- 테스트는 Mock TranslationClient와 별도 메모리 H2, 고정 시각에서 수행했다.
- SQL 오류 격리 테스트는 별도 JDBC 연결/트랜잭션과 원본 트랜잭션 사용 가능 여부를 검증했다.
  실제 PostgreSQL 장애를 유발한 검증은 하지 않았다.
- Gradle build -x test 성공. 전체 JUnit/대규모 회귀/브라우저 전체/부하 테스트 없음.
- 실제 Gemini 호출 없음. 실제 Supabase 데이터·스키마 변경 없음.
- 독립 코드 검토 2회: 주요 결함 없음. Git diff --check 공백 오류 없음.

worker 설정과 남은 사항
.env 및 환경 변수, worker=false는 변경하지 않았다. 비활성 상태에서도 큐 등록과 캐시 조회는 동작한다.
자동 처리가 필요할 때 사용자가 GEMINI_TRANSLATION_WORKER_ENABLED=true로 바꾸고 서버를 재시작한다.
GEMINI_API_KEY / GEMINI_MODEL=gemini-3.5-flash-lite와 기존 테이블 준비 상태를 유지한다.
요청 제한, 예산, 중복 보호, 재시도는 2-A 설정 그대로다.
기존 공개 행사 중 영어 캐시가 없는 데이터의 일괄 backfill은 이번 범위에 포함하지 않았다.
공지/알림/커뮤니티 동적 번역, WebSocket/SSE/자동 폴링은 구현하지 않았다.

Git 보호
feat/다국어지원 유지. Git은 status/diff/branch --show-current 읽기만 사용했다.
기존 미커밋 변경 보존, 인덱스/이력/원격 변경 및 커밋/Push/브랜치 이동 없음.
2-B에서 종료한다.
