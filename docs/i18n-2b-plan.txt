Busan Play 2-B 구현 계획

기존 1-A~2-A와 미커밋 변경을 보존한다. Git 읽기만 사용한다.
.env/worker/API 한도/DB 스키마와 실제 Supabase 데이터는 변경하지 않는다.
테스트는 별도 출력 및 메모리 H2, mock Client만 사용한다.

조사: 공개 전환은 DepositService.payDeposit에서 모든 회차 보증금 납부 후 일어난다.
EventService.update는 PUBLISHED 수정 자체를 거부한다. 이 업무 정책은 변경하지 않는다.
JPA Event 저장 lifecycle을 이용해 현재 및 향후 허용된 공개/콘텐츠 변경을 감지한다.
새 lifecycle은 공개 행사에만 AFTER_COMMIT 알림을 내고 기존 요청 서비스로 등록한다.
동일 해시는 2-A 캐시/유일 작업 제약으로 재번역하지 않는다. 예외는 부가 기능 안에서 차단한다.
JPA를 통하지 않는 직접 SQL/bulk update는 현재 업무 코드에 없으며 자동 감지 대상이 아니다.

상세와 공개 목록/검색/메인 페이지의 EventService DTO 조합에 presentation helper를 적용한다.
한국어/비공개/기업 수정 폼/관리자 원본은 번역하지 않는다. Mustache/Controller는 유지한다.
목록은 기존 페이지 Event 원문으로 해시를 만들고 cache table을 1회 IN 조회한다.
완료/동일 해시만 DTO에 적용한다. 누락/실패/오래된 번역은 원문을 유지한다.
ja/zh-CN cache miss만 커밋 후 기존 requestTranslation으로 작업 등록한다.
누락 작업 등록 시 2-A가 수행하는 개별 잠금/캐시 재확인은 동시성 보호를 위해 유지한다.
en 조회 자체에서는 신규 작업을 만들지 않는다. 공개/원문 변경 때만 사전 요청한다.

검증: 커밋/롤백/공개 상태, 동일 해시, 수정 stale, ja/zh-CN miss,
상세/목록 DTO 적용과 필드 보존, 등록/조회 오류 fallback, cache hit 비호출만 핵심 테스트.
실제 Gemini API, Supabase 데이터 수정, 전체 JUnit/UI/부하 테스트는 실행하지 않는다.
마지막으로 build -x test 및 diff 공백 확인을 수행한다.
